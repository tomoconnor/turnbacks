# Database schema

PostgreSQL (17 or 18) is the single source of truth. The schema is defined by goose migrations in
`db/migrations/` (embedded in the binary and applied on start-up unless `TURNBACKS_MIGRATE_ON_START=false`).
Queries are hand-written SQL in `db/queries/` and compiled to Go by sqlc into `db/sqlc/`.

Conventions:

- Primary keys are UUIDs. Turnback IDs are **generated by the client** (they are the idempotency key).
- All timestamps are `timestamptz`; connections use `TimeZone=UTC`.
- Money is `bigint` **minor units** (e.g. pence). Percentages are integers 0–100.
- Every table that can contain seeded demonstration data has `is_demo boolean`.
- Enumerations are `text` with `CHECK` constraints (simple to migrate, readable in SQL).

## Entity overview

```text
categories 1─* problems 1─* turnbacks *─1 teams
                 │  ╰─ merged_into_id → problems
                 ├─* remediations
                 ╰─* change_markers (problem_id NULL = organisation-wide)
webhooks 1─* webhook_deliveries          inbound_hooks
org_settings (single row)   admin_audit   slack_request_log (Slack replay protection)
```

## Tables

### `turnbacks` — one row per occurrence

| Column | Type | Notes |
| --- | --- | --- |
| `id` | uuid PK | Client-generated; `INSERT … ON CONFLICT (id) DO NOTHING` gives idempotent submission |
| `problem_id` | uuid → problems | Merges move rows to the target problem |
| `reporter` | text, nullable | Pseudonymous reporter key: `ip:<address>` or `user:<sso user>` (web, CLI, API), `slack:<team>/<user>`, `mattermost:<team>/<user>`, `teams:<id>` or `hook:<name>[:<label>]`. Counts towards "people affected"; visible to admins only; cleared by reporter retention |
| `team_id` | uuid → teams, nullable | Team chosen by the reporter (remembered per device / CLI config) |
| `undo_token_hash` | bytea, nullable | SHA-256 of the one-time undo token (valid 15 minutes) |
| `duration_minutes` | integer | `CHECK 1..1440` |
| `duration_estimated` | boolean | Whether the reporter estimated the duration (default true) |
| `note` | text, nullable | ≤ 1000 characters; cleared by note retention |
| `occurred_at` | timestamptz | When it happened (preserved for offline submissions) |
| `submitted_at`, `updated_at` | timestamptz | Server times |
| `source` | text | `web`, `pwa_offline`, `api`, `cli`, `slack`, `webhook`, `mattermost`, `teams` |
| `is_demo` | boolean | Seeded data |
| `batch_id` | uuid, nullable | Shared by occurrences recorded together with a quantity > 1 (equal to the first occurrence's `id`); used for whole-batch undo and to identify bulk entries |

Indexes: `(occurred_at)`, `(problem_id, occurred_at)`, `(team_id, occurred_at)`,
partial `(reporter, occurred_at) WHERE reporter IS NOT NULL`, partial `(batch_id) WHERE batch_id IS NOT NULL`.

There is **no counter column anywhere**: totals are always `count(*)`/`sum()` over these rows.

### `problems`

| Column | Notes |
| --- | --- |
| `title` (3–120 chars), `description` (≤ 4000) | Trigram GIN index on `lower(title)` for search and duplicate suggestions |
| `category_id` → categories | |
| `status` | `active`, `monitoring`, `resolved`, `archived`. `resolved_at` is maintained automatically |
| `alias` | Optional unique short name (`^[a-z0-9][a-z0-9-]{0,31}$`), e.g. `vpn` for Slack |
| `external_url` | Optional http(s) link to an issue tracker |
| `merged_into_id` → problems | Set when merged; such problems are archived, hidden from lists, and late submissions are redirected |
| `created_by` → users (`SET NULL`) | |

### `remediations`

`problem_id`, `implemented_on date`, `description`, `implementation_cost_minor`, `annual_cost_minor`,
`expected_reduction_pct (0–100)`, `created_by`, `created_at`, `is_demo`. Costs here are **actual or planned
expenditure**, distinct from estimated productivity cost.

### `change_markers`

A point in time when something changed, used for before/after comparisons.

| Column | Notes |
| --- | --- |
| `occurred_at` | When the change happened (indexed) |
| `title` (1–200), `description` (≤ 2000), `url` (http(s), optional) | |
| `problem_id` → problems (`ON DELETE CASCADE`), nullable | NULL for an organisation-wide change |
| `source` | `web`, `api`, `cli`, `webhook` |
| `created_by` | Reporter key of whoever marked it (admin-only) |
| `is_demo`, `created_at` | The seed adds a marker at each demo remediation |

### `teams`, `categories`

Teams: `name` (case-insensitively unique), `active`, optional `hourly_rate_minor`, optional `headcount` (for reporting participation). Categories: `name`,
`description`, `active`, `sort_order`; the seven default categories are inserted by the first migration.

### `org_settings` (single row, `id = 1`)

| Column | Default | Purpose |
| --- | --- | --- |
| `org_name` | “My Organisation” | Display |
| `currency` | `GBP` | ISO 4217 |
| `default_hourly_rate_minor` | 5000 (£50.00) | Fully loaded hourly employment cost |
| `reporting_timezone` | `Europe/London` | Day/week/month boundaries |
| `recoverable_pct` | 100 | Default business-case assumption |
| `large_duration_minutes` | 120 | Durations above this need confirmation |
| `note_retention_days` | NULL (keep) | Clear notes older than N days |
| `reporter_retention_days` | NULL (keep) | Remove reporter links older than N days |

### Administration and integration tables

| Table | Purpose |
| --- | --- |
| `slack_request_log` | SHA-256 of accepted Slack signatures (replay protection), pruned after 15 minutes |
| `webhooks` | Outbound webhooks: `name`, `url`, `format` (`json`, `slack`, `markdown`, `teams`), `events text[]`, signing `secret`, `enabled` |
| `webhook_deliveries` | Queue and history: `event`, `payload jsonb` (the envelope), `status` (`pending`, `delivered`, `failed`), `attempts`, `next_attempt_at` (also the worker lease), `last_status_code`, `last_error`. Partial index on due pending rows. Non-pending rows are deleted after 30 days; deleting a webhook cascades |
| `inbound_hooks` | Inbound webhooks: `name`, `kind` (`json`, `mattermost`, `teams`), `token_hash` (SHA-256; json and mattermost) or `hmac_secret` (teams), `enabled`, `last_used_at` |
| `admin_audit` | Admin audit log: `at`, `admin`, `via` (`certificate`, `sso`, `dev`), `method`, `action` (route pattern), `target`, `status`, `client`, `request_id`. Identity primary key; kept indefinitely |

## Aggregation queries

All analytics are in `db/queries/analytics.sql`:

- `AnalyticsSummary` — totals, distinct reporters (people affected), unattributed and estimated counts.
- `AnalyticsTimeseries` — `generate_series` of day/week/month buckets in the reporting timezone,
  left-joined so empty buckets appear as zero.
- `AnalyticsProblemRanking` — per-problem totals, ranked by count, minutes or cost, with window
  functions for share and cumulative (Pareto) share; paginated.
- `AnalyticsCategoryBreakdown`, `AnalyticsTeamBreakdown` (with team member counts for participation).

Cost in every query is `round(sum(duration_minutes × coalesce(team.hourly_rate_minor, org.default_hourly_rate_minor)) / 60)`,
computed in `NUMERIC` — see [financial-model.md](financial-model.md).

## Migrations

```sh
turnbacks migrate status
turnbacks migrate up
turnbacks migrate down   # one step
```

Add a migration by creating `db/migrations/0000N_description.sql` with `-- +goose Up` / `-- +goose Down`
sections, then run `make sqlc` if queries change.
