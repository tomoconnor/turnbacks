# Kubernetes: Helm and Argo CD

```text
deploy/
  helm/turnbacks/            Helm chart (app + CloudNativePG database)
  environments/<env>/        per-environment values (staging, production)
  argocd/
    project.yaml             AppProject scoping repos, namespaces and cluster resources
    cnpg-operator.yaml       Application installing the CloudNativePG operator (chart 0.29.1 / operator 1.30.1)
    applicationset.yaml      one Application per environment (turnbacks-staging, turnbacks-production)
  examples/
    external-secret.yaml     Slack signing secret from a secret manager (External Secrets Operator)
    barman-objectstore.yaml  object storage for CloudNativePG backups (Barman Cloud plugin)
```

## What the chart deploys

| Resource | Notes |
| --- | --- |
| Deployment | Distroless non-root image, read-only root filesystem, all capabilities dropped, `RuntimeDefault` seccomp, no service-account token. Rolling updates with `maxUnavailable: 0`. Startup/liveness probe `/healthz`, readiness `/readyz` |
| CloudNativePG `Cluster` | `<release>-db`, database and owner `turnbacks`. Credentials are generated by the operator in Secret `<release>-db-app` and read by the app from its `uri` key, so no database password exists in git or values. Connections use TLS (`PGSSLMODE=require`). Annotated `helm.sh/resource-policy: keep` and Argo CD `Delete=false` so uninstalling or pruning never deletes the database; sync wave `-1` so it is created before the app |
| `ScheduledBackup` | Optional (`database.cloudnativepg.scheduledBackup`) |
| Service, Ingress | Ingress optional; host defaults to the `publicURL` host |
| HPA, PodDisruptionBudget | HPA optional; PDB on by default (`minAvailable: 1`) |
| NetworkPolicy | Optional. Ingress only from the ingress controller (configurable); egress only to DNS, the database pods and any `networkPolicy.webhookEgress` rules (needed for outbound webhooks) |
| Identity | `identity.mode=ip` (default) or `header` for single sign-on through your ingress's auth annotations (`auth-url`, `auth-response-headers`); see [identity.md](identity.md) |
| ConfigMap | All non-secret settings; a checksum annotation rolls pods when it changes |
| `helm test` | Runs `turnbacks healthcheck` against the Service |

Migrations run on start-up under a database lock, so several replicas can start together. Pods wait
up to `config.dbWait` (default 120 s) for PostgreSQL, which covers CloudNativePG bootstrapping on a
first install.

## Prerequisites

1. **CloudNativePG operator** (1.25+). Install it with `deploy/argocd/cnpg-operator.yaml`, or
   `helm install cnpg cnpg/cloudnative-pg -n cnpg-system --create-namespace`. To use an existing database
   instead, set `database.cloudnativepg.enabled=false` and `database.external.existingSecret` to a Secret
   whose `uri` key holds the connection URL.
2. **Image**: push the image to a registry and set `image.repository`. The CI workflow publishes
   `ghcr.io/<owner>/turnbacks:<sha>` and `:main` on every push to `main`.
3. **Admin CA**: create a Secret holding the admin CA certificate (`ca.crt` only, never `ca.key`):
   `kubectl -n turnbacks create secret generic turnbacks-admin-ca --from-file=ca.crt=ca/ca.crt`
   ([admin-certificates.md](admin-certificates.md)). If Slack is used, also a Secret with the signing
   secret (key `slack-signing-secret`), via External Secrets or Sealed Secrets; never commit it
   (`deploy/examples/external-secret.yaml`).
4. **ingress-nginx** for admin client certificates (the chart adds its `auth-tls-*` annotations when
   `admin.clientCA.existingSecret` is set). For other controllers set `admin.ingressNginx=false` and
   configure the equivalent. cert-manager, if you use the example ingress annotations.

## Helm

```sh
helm upgrade --install turnbacks deploy/helm/turnbacks \
  --namespace turnbacks --create-namespace \
  --set image.repository=ghcr.io/your-org/turnbacks --set image.tag=<sha> \
  --set publicURL=https://turnbacks.example.com \
  --set admin.clientCA.existingSecret=turnbacks-admin-ca \
  --set config.trustedProxies=10.42.0.0/16 \
  --set ingress.enabled=true --set ingress.className=nginx
helm -n turnbacks test turnbacks
```

All options are documented in [`values.yaml`](../deploy/helm/turnbacks/values.yaml). The chart fails to
render with a clear message if the ingress is enabled without `ingress.host` or `publicURL`.

**Trusted proxies matter.** Turnbacks has no accounts; each report is attributed to the client address
(one VPN address per person) for "people affected" and the admin audit view. Set
`config.trustedProxies` to your ingress controller's pod network (and *not* the VPN client range), and
make sure the ingress passes the client address in `X-Forwarded-For` (ingress-nginx does by default;
behind a cloud load balancer you may need `externalTrafficPolicy: Local` or PROXY protocol). Check
Admin → Reports after deploying: the addresses should be VPN addresses, not the ingress pods.

## Argo CD

1. Replace `YOUR-ORG` in `deploy/argocd/*.yaml` and `deploy/environments/*/values.yaml`, and set real
   hostnames, trusted-proxy ranges and image tags.
2. Apply the project and applications (Argo CD 2.10+; the ApplicationSet uses multi-source values and
   `templatePatch`):

   ```sh
   kubectl apply -f deploy/argocd/project.yaml
   kubectl apply -f deploy/argocd/cnpg-operator.yaml
   kubectl apply -f deploy/argocd/applicationset.yaml
   ```

3. Staging syncs automatically from `main`. Production does not auto-sync: promote by setting the
   production `revision` (ApplicationSet) and image tag (values) to a release, then sync.

## Backups

Enable continuous backup with the [Barman Cloud plugin](https://cloudnative-pg.io/plugin-barman-cloud/):
install the plugin, create an `ObjectStore` (`deploy/examples/barman-objectstore.yaml`), and use the
`database.cloudnativepg.plugins` and `scheduledBackup` values shown in
`deploy/environments/production/values.yaml`. Restore by bootstrapping a new `Cluster` from the
backup (`bootstrap.recovery`) and pointing `database.external` at it, or by following the
CloudNativePG recovery guide. Logical `pg_dump` backups, as in [backup-restore.md](backup-restore.md), also work:
`kubectl exec` into the primary (`<release>-db-1`).

## Verified

The chart was installed into a throwaway k3d cluster (Kubernetes 1.31) with CloudNativePG operator
1.30.1, two app replicas and the NetworkPolicy enabled. Checks:

- the database bootstrapped while the app waited for it, then all migrations applied;
- `helm test` passed (with the NetworkPolicy in force);
- `tb` recorded reports through the Service (`source: cli`);
- the audit view showed each report's reporter address.

That run predates admin client certificates, single sign-on identity and webhooks. Their chart
settings (ingress-nginx client-certificate and auth annotations, `networkPolicy.webhookEgress`) render
and lint, but have not yet been exercised on a live cluster.

An earlier revision was also checked for a zero-downtime rolling restart, survival of the database
after `helm uninstall`, and server-side dry-run validation of the Argo CD manifests against the
Argo CD v2.13 CRDs.

Admin client certificates were verified end to end with the Docker/Caddy stack, not yet on
Kubernetes. The chart's ingress-nginx annotations render as intended (`helm template`), but have not
been exercised against a live ingress-nginx.

Not verified: a live Argo CD sync (the repository needs a remote first), backups to object storage,
client-address attribution and client certificates behind a real ingress controller with TLS.
